## 1. 模块概述

### 1.1 目的

在 HarmonyOS / OpenHarmony 设备上提供一个**极简浏览器外壳**：应用启动后即全屏进入一个由 Electron 渲染的浏览区域，用户可以通过一个常驻的浮动入口随时输入网址并跳转，无需任何菜单栏、标签页或工具栏。

### 1.2 解决的问题

| 痛点 | 本模块的解法 |
|------|-------------|
| Electron 在鸿蒙上的原生窗口与系统状态栏、导航条并存，观感割裂 | 宿主窗口进入沉浸式全屏，浏览器内容铺满整屏 |
| 每次访问站点都要重新输入地址 | 最后一次确认的网址持久化到本地，下次启动自动加载 |
| 没有地址栏的「壳」应用无法导航 | 左下角浮动按钮 + 底部输入面板，按需展开、确认即收起 |
| 不同形态设备（手机/平板/2in1/TV）屏幕差异大 | 三档响应式布局，跟随窗口尺寸与横竖屏切换自动重排 |

### 1.3 范围

**包含：**

- 全屏（覆盖系统状态栏与底部导航条）宿主窗口；
- 全屏 Electron 浏览区域；
- 本地 URL 读取 → 加载；无 URL → 空页面 + 底部输入框；
- 左下角浮动按钮 → 底部输入框展开 → 确认导航 → 输入框收起；
- URL 本地持久化；
- 手机 / 平板 / 2in1 / TV 四类设备形态与横竖屏响应式布局。

**不包含：**

- 多标签页、前进/后退/刷新/书签/历史记录（属后续迭代）；
- 下载管理、密码填充、隐私模式；
- 应用商店上架与正式签名（本工程使用调试签名）。

| 编号 | 用户故事 |
|------|---------|
| US-001-01 | 作为用户，我希望打开应用后立刻看到上次访问的网页并占满整个屏幕，这样我不用每次重新输入地址 |

## 3. 功能需求

### 3.1 全屏与沉浸式（FR-001-001 ~ 003）

- **FR-001-001**：应用主窗口 MUST 采用全屏布局（`setWindowLayoutFullScreen(true)`），页面绘制区域覆盖系统状态栏与底部导航条所占区域。
- **FR-001-002**：应用 MUST 隐藏系统状态栏与底部导航指示条；若设备形态不支持该能力（如 2in1 无状态栏），失败 MUST 被捕获并仅记录日志，不得导致启动失败。
- **FR-001-003**：在 2in1 / PC 形态下，主窗口 MUST 最大化并进入沉浸式（隐藏标题栏与 Dock 悬浮），使浏览区域铺满屏幕。

### 3.2 启动加载（FR-001-010 ~ 013）

- **FR-001-010**：应用启动时 MUST 读取本地存储中的「最后访问 URL」。
- **FR-001-011**：本地存在**合法**URL 时，浏览区域 MUST 立即加载该 URL，且底部输入面板 MUST 保持收起。
- **FR-001-012**：本地不存在 URL，或本地值已非法时，浏览区域 MUST 展示空页面，且底部输入面板 MUST 自动展开（供首次输入）。
- **FR-001-013**：启动恢复逻辑 MUST NOT 把非法或残缺的网址送入浏览器内核；遇到非法值 MUST 视为「无 URL」处理并清理状态。

### 3.3 浮动入口与地址输入（FR-001-020 ~ 026）

- **FR-001-020**：界面左下角 MUST 常驻一个圆形浮动按钮（输入面板展开时隐藏）。
- **FR-001-021**：点击浮动按钮 MUST 在屏幕下方展开地址输入面板，且面板内输入框 MUST 自动获得焦点。
- **FR-001-022**：输入面板 MUST 提供「前往」确认与「✕」收起两种操作。
- **FR-001-023**：确认时 MUST 对输入做规整：去掉首尾空白；无协议前缀时补 `https://`。
- **FR-001-024**：确认时 MUST 校验输入：仅接受 `http` / `https`，主机名须为合法域名或 `localhost`，可带 1~5 位端口；不合法 MUST 就地提示错误且不发起导航。
- **FR-001-025**：校验通过后 MUST 依次执行：写入本地存储 → 通知浏览器内核导航 → 收起输入面板。
- **FR-001-026**：输入框内按软键盘「前往（Go）」MUST 与点击「前往」按钮等价。

### 3.4 浏览器内核导航（FR-001-030 ~ 033）

- **FR-001-030**：浏览器内核 MUST 在同一个窗口内完成跳转，不得为每次导航新建原生窗口。
- **FR-001-031**：页面内 `target="_blank"` / `window.open` 触发的新窗口请求 MUST 收敛到当前窗口打开。
- **FR-001-032**：非 `http/https/file` 协议（如 `mailto:`）MUST 交由系统处理，不得在浏览区域内直接加载。
- **FR-001-033**：导航失败 MUST 回退到空页面，并记录失败原因（错误码 + 描述 + URL）到日志。

### 3.5 本地持久化（FR-001-040 ~ 041）

- **FR-001-040**：确认过的 URL MUST 持久化到应用偏好存储（键 `last_url`），应用重启后仍可读取。
- **FR-001-041**：持久化失败 MUST 记录日志，且 MUST NOT 阻断本次导航。

### 3.6 响应式布局（FR-001-050 ~ 053）

- **FR-001-050**：布局 MUST 依据窗口宽度划分为三档：紧凑（< 600vp，典型手机竖屏）、常规（600~839vp，典型平板）、宽屏（≥ 840vp，典型 2in1 / TV）。
- **FR-001-051**：窗口尺寸变化（含横竖屏切换、PC 窗口拉伸、软键盘弹出导致的可视区变化）MUST 触发实时重排。
- **FR-001-052**：紧凑档下输入面板宽度 MUST ≥ 视口宽度的 90%，宽屏档下 MUST 限制最大宽度（≤ 760vp）以避免输入行过长。
- **FR-001-053**：浮动按钮与输入面板的尺寸、字号 MUST 随档位变化（紧凑档整体缩小）。

## 4. 关键实体

| 实体 | 说明 | 关键属性 |
|------|------|---------|
| 最后访问 URL | 用户最后一次确认的有效网址 | `last_url`（字符串，持久化） |
| 外壳状态 | ArkTS 与浏览器内核之间的导航契约 | `url`（字符串）、`seq`（递增整数） |
| 导航请求 | 一次由用户确认触发的跳转 | 规整后的 URL + 自增序号 |

## 5. 验收场景

### 场景 1：首次启动（无本地 URL）

- **Given** 应用从未保存过 URL
- **When** 用户启动应用
- **Then** 浏览区域显示空页面，底部自动展开地址输入面板，输入框获得焦点

### 场景 2：再次启动（有本地 URL）

- **Given** 上次使用中确认过 `https://www.baidu.com`
- **When** 用户重新启动应用
- **Then** 浏览区域直接加载该网址并铺满全屏，输入面板保持收起

### 场景 3：通过浮动按钮导航

- **Given** 应用正在显示某个网页
- **When** 用户点击左下角浮动按钮，输入 `www.threejs.org`，点击「前往」
- **Then** 输入被规整为 `https://www.threejs.org`，浏览区域跳转该站点，输入面板收起，浮动按钮重新出现

### 场景 4：非法输入

- **Given** 输入面板已展开
- **When** 用户输入 `https://a.comhttps://b.com` 并确认
- **Then** 面板下方提示「请输入有效网址，例如 www.baidu.com」，页面不跳转，面板保持展开

### 场景 5：页内链接跳转

- **Given** 已加载 `https://www.baidu.com`
- **When** 用户点击顶部「新闻」链接
- **Then** 在同一个浏览区域打开新闻首页，浮动按钮仍然可用

### 场景 6：页内新窗口请求

- **Given** 网页中存在 `target="_blank"` 的链接
- **When** 用户点击该链接
- **Then** 目标页面在当前浏览区域打开，不出现第二个系统窗口

### 场景 7：横竖屏 / 窗口拉伸

- **Given** 应用处于宽屏档布局
- **When** 用户将窗口拉窄到 600vp 以下，或把设备转为竖屏
- **Then** 输入面板自动切换为紧凑档宽度与更小字号，布局无溢出、无遮挡

## 6. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 浮动按钮点击到输入面板展开无可感知延迟（≤ 100ms）；导航请求从确认到内核收到 ≤ 1s（状态文件轮询周期 300ms） |
| 可靠性 | 任何窗口能力/持久化/文件写入失败均不得导致应用崩溃；启动流程 MUST 在能力缺失时仍能进入浏览界面 |
| 可观测性 | 关键路径（状态文件路径、发布序号与 URL、导航成功/失败）MUST 输出 `hilog` / 控制台日志，便于真机排障 |
| 兼容性 | `default`(phone) / `tablet` / `2in1` / `tv` 四类设备形态；API 20 及以上 |
| 可用性 | 输入面板展开时输入框自动聚焦；错误提示文本与界面语言一致（中文） |

## 7. 假设与约束

- 浏览器内容的渲染与网络能力由 Electron（v37.2.3）内核提供，本模块不重复实现 WebView。
- ArkTS 侧与内核侧的通信必须走应用自有通道，不依赖 `web_engine` 未导出的内部符号。
- 应用仅在**获得有效签名**（华为 AGC profile）后可安装到 HarmonyOS 真机；OpenHarmony 自签名材料仅适用于 OpenHarmony 设备。
- 平板「非 PC 模式」下若系统保留状态栏，原生窗口可能留有顶部内边距（见 `specs/001-electron-shell/plan.md` 已知限制）。
